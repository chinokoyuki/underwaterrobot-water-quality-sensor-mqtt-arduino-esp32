## 1. 更正概述

本次更正涉及三项核心变更：

| 序号 | 变更内容 | 原因 |
|------|---------|------|
| 1 | 氨氮传感器 → 溶解氧传感器 | 氨氮传感器与溶解氧传感器实为同一硬件，需统一命名为溶解氧 |
| 2 | 移植 Bionic manta ray 工程的传感器计算公式 | 原工程部分公式不准确或缺少温度补偿，需对齐参考实现 |
| 3 | 修正华为云 IoTDA MQTT 上报数据 | 属性名、属性数量、service_id 等存在不一致，需与物模型完全对齐 |

## 2. 变更一：氨氮传感器合并为溶解氧传感器

### 2.1 背景

原工程中存在两个概念：
- **氨氮传感器**（`AMMONIA_NITROGEN_PIN` = A3）：实际硬件接入的传感器
- **溶解氧传感器**（`DissolvedOxygen`）：仅在华为云物模型中定义，代码中上报占位值 `0.0f`

经确认，A3 引脚接入的传感器**实为溶解氧传感器**，原"氨氮"命名为误称。因此将两者合并，统一使用**溶解氧（Dissolved Oxygen, DO）**命名，保留原氨氮传感器的引脚（A3）和硬件配置。

### 2.2 具体变更

| 位置 | 变更前 | 变更后 |
|------|--------|--------|
| `WaterQualitySensor.h` 引脚定义 | `AMMONIA_NITROGEN_PIN A3` | `DO_PIN A3` |
| `WaterQualitySensor.h` 常量定义 | `AMMONIA_REF_VOLTAGE`, `AMMONIA_MAX_VALUE`, `AMMONIA_COEFFICIENT` | `DO_REF_VOLTAGE`, `DO_MAX_VALUE`, `DO_COEFFICIENT` |
| `WaterQualitySensor.h` 超标阈值 | `AMMONIA_MAX_NORMAL 10.0f`（氨氮 > 10 超标） | `DO_MIN_NORMAL 2.0f`（溶解氧 < 2 超标） |
| `WaterQualitySensor.h` 函数声明 | `readAmmoniaNitrogen()` | `readDissolvedOxygen()` |
| `WaterQualitySensor.h` 函数参数 | `isWaterQualityNormal(float ph, float tds, float ammonia, ...)` | `isWaterQualityNormal(float ph, float tds, float dissolvedOxygen, ...)` |
| `WaterQualitySensor.h` 校准系数 | `_ammoniaCoefficient` | `_doCoefficient` |
| `WaterQualitySensor.cpp` 函数实现 | `readAmmoniaNitrogen()` 线性公式 | `readDissolvedOxygen()` 查表+温度补偿公式 |
| `WaterQualitySensor.cpp` 水质判断 | `ammonia > AMMONIA_MAX_NORMAL` | `dissolvedOxygen < DO_MIN_NORMAL` |
| `WaterQualitySensor.cpp` 校准存储 | `"ammoniaCoeff"` | `"doCoeff"` |
| `main.cpp` SensorData 字段 | `float ammonia` | `float dissolvedOxygen` |
| `main.cpp` 数据采集 | `readAmmoniaNitrogen()` | `readDissolvedOxygen()` |
| `main.cpp` 串口输出 | `氨氮(mg/L)` | `溶解氧(mg/L)` |

### 2.3 超标判断逻辑变更

氨氮和溶解氧的超标判断逻辑**方向相反**：

| 传感器 | 变更前 | 变更后 |
|--------|--------|--------|
| 氨氮 | 氨氮 > 10 mg/L → 超标（值越大越差） | — |
| 溶解氧 | — | 溶解氧 < 2 mg/L → 超标（值越小越差） |

溶解氧过低意味着水体缺氧，水质恶化，因此判断方向为"低于阈值即超标"。

## 3. 变更二：传感器计算公式移植

公式来源：`C:\Users\arisc\Desktop\Bionic manta ray\public\data\dataAccess.js`

### 3.1 pH 传感器

| 项目 | 变更前 | 变更后 |
|------|--------|--------|
| 公式 | `pH = -12.384 * V + 40.93` | `pH = -12.384 * V + 40.93` |
| 单位 | V = 伏特 | V = 伏特 |
| 变更 | **无变化**，原公式已与参考工程一致 | — |

### 3.2 TDS 传感器

| 项目 | 变更前 | 变更后 |
|------|--------|--------|
| 公式 | `TDS = (V / 3.3) * 133.42 * tempComp` | `TDS = 66.71*V³/1e9 - 127.93*V²/1e6 + 428.7*V/1e3` |
| 单位 | V = 伏特 | V = 毫伏 |
| 温度补偿 | 有（固定 25℃） | 无（三次多项式已内含特性曲线） |
| 变更性质 | **重大变更** | 线性 → 三次多项式拟合 |

**详细公式（C++ 实现）：**

```cpp
float v = tdsVoltageMv;  // 电压（mV）
float tdsValue = 66.71f * v * v * v / 1000000000.0f
               - 127.93f * v * v / 1000000.0f
               + 428.7f * v / 1000.0f;
```

### 3.3 浊度传感器

| 项目 | 变更前 | 变更后 |
|------|--------|--------|
| 公式 | `turbidity = -865.68 * ADC + 2047.19` | `turbidity = -865.68 * V_compensated + 2047.19` |
| 输入 | ADC 原始值（0-4095） | 电压值（V），含温度补偿 |
| 温度补偿 | **无** | `V_compensated = (V_mV - (-0.0192 * (T - 25))) / 1000` |
| 单位 | ADC 原始值 | NTU（近似） |
| 变更性质 | **重大变更** | 增加温度补偿 + 输入从 ADC 改为电压 |

**详细公式（C++ 实现）：**

```cpp
float turbVoltageMv = turbVoltage * 1000.0f;
float compensatedVoltageMv = turbVoltageMv - (-0.0192f * (waterTemp - 25.0f));
double result = -865.68 * (compensatedVoltageMv / 1000.0) + 2047.19;
```

### 3.4 溶解氧传感器

| 项目 | 变更前（氨氮） | 变更后（溶解氧） |
|------|--------------|----------------|
| 公式 | `DO = (V / 3.3) * 50 * coeff` | `DO = ((V_mV - 55) * 769 / 805 - (842 - DoList[T])) / 100` |
| 温度补偿 | 无 | 查表补偿（0~40℃ 饱和溶解氧电压） |
| 最大量程 | 50 mg/L | 20 mg/L |
| 变更性质 | **重大变更** | 简单线性 → 查表+温度补偿 |

**详细公式（C++ 实现）：**

```cpp
// 饱和溶解氧电压查表（0~40℃，共41个数据点）
static const int DO_LIST[] = {
    1462, 1422, 1383, 1346, 1311, 1277, 1245, 1214, 1184, 1156,
    1129, 1103, 1078, 1054, 1031, 1008, 987, 966, 947, 928,
    909, 891, 874, 858, 842, 826, 811, 797, 783, 769,
    756, 743, 730, 718, 707, 695, 684, 673, 663, 653, 643
};

float doValue = ((doVoltageMv - 55.0f) * 769.0f / 805.0f
                - (842.0f - (float)DO_LIST[tempIndex])) / 100.0f;
```

### 3.5 DS18B20 水温传感器

**无变化**，继续使用 OneWire + DallasTemperature 库读取。

### 3.6 MS5837 深度传感器

**无变化**，继续使用 I2C 驱动 + 二阶温度补偿算法。

### 3.7 公式变更对比汇总

```
            变更前                          变更后
pH:     -12.384*V+40.93          →  -12.384*V+40.93     (无变化)
TDS:    (V/3.3)*133.42*tempComp  →  66.71*V³/1e9 - 127.93*V²/1e6 + 428.7*V/1e3
浊度:   -865.68*ADC+2047.19      →  -865.68*V_comp+2047.19 (增加温度补偿)
氨氮→DO: (V/3.3)*50*coeff        →  ((V_mV-55)*769/805-(842-DoList[T]))/100
```

## 4. 变更三：华为云 MQTT 上报数据修正

### 4.1 已修复的问题

#### 问题 1：多余参数导致 snprintf 忽略溶解氧

**原代码（main.cpp 第196-208行）：**
```cpp
snprintf(properties, sizeof(properties),
    "{...\"depthSensorOnline\":%s}",
    ..., sensorData.depthSensorOk ? "true" : "false",
    0.0f   // 溶解氧传感器暂未接入，上报占位值 0.0
);
```

问题：`0.0f` 是 `snprintf` 的第11个参数，但格式字符串只有10个占位符，该参数被静默忽略。溶解氧数据从未被实际上报。

**修复后：** 移除多余参数，溶解氧作为正式属性上报。

#### 问题 2：属性名 ammoniaNitrogen → dissolvedOxygen

原代码上报 `"ammoniaNitrogen"`，但实际硬件是溶解氧传感器，应上报 `"dissolvedOxygen"`。

**修复后：** 属性名改为 `dissolvedOxygen`。

#### 问题 3：浊度单位不正确

原代码注释"返回ADC原始值"，物模型中浊度类型为 `int`。移植公式后浊度计算结果为浮点数，单位更正为 NTU。

**修复后：** 物模型中浊度类型改为 `decimal`，单位为 NTU。

### 4.2 上报属性变更对照

| 序号 | 变更前属性名 | 变更后属性名 | 说明 |
|------|-------------|-------------|------|
| 1 | `pH` | `pH` | 无变化 |
| 2 | `TDS` | `TDS` | 无变化 |
| 3 | `turbidity` | `turbidity` | 类型从 int → decimal，单位 ADC → NTU |
| 4 | `ammoniaNitrogen` | `dissolvedOxygen` | 氨氮 → 溶解氧 |
| 5 | `waterTemp` | `waterTemp` | 无变化 |
| 6 | `depth` | `depth` | 无变化 |
| 7 | `depthPressure` | `depthPressure` | 无变化 |
| 8 | `depthSensorTemp` | `depthSensorTemp` | 无变化 |
| 9 | `waterQualityNormal` | `waterQualityNormal` | 无变化 |
| 10 | `depthSensorOnline` | `depthSensorOnline` | 无变化 |
| 11 | `DissolvedOxygen`（占位0.0） | **已移除** | 合并到第4项 |

**属性总数：11 → 10**（移除了占位的 `DissolvedOxygen`，替换 `ammoniaNitrogen` 为 `dissolvedOxygen`）

## 7. 校准参数迁移说明

ESP32 Flash 中 Preferences 存储的校准参数 key 已变更：

| 旧 Key | 新 Key | 说明 |
|--------|--------|------|
| `ammoniaCoeff` | `doCoeff` | 氨氮系数 → 溶解氧系数 |
| `phOffset` | `phOffset` | 无变化 |
| `tdsCoeff` | `tdsCoeff` | 无变化（但 TDS 公式已完全改变，旧系数不再适用） |

> **注意**：由于 TDS 公式从线性改为三次多项式，`_tdsCoefficient` 在新公式中已不再使用。如果之前存储了自定义的 `tdsCoeff` 值，它不会影响新的 TDS 计算，但也不会报错，只是被忽略。

**建议**：首次烧录新固件后，可在串口监视器中确认传感器读数是否正常。如需清空旧校准参数，可在代码中调用 `pref.clear()` 或手动删除 Preferences 命名空间。

## 附录：原 dataAccess.js 公式源码（供参考）

```javascript
// 来源: C:\Users\arisc\Desktop\Bionic manta ray\public\data\dataAccess.js

// 溶解氧查表数据（0~40℃对应的饱和溶解氧电压 mV）
static DoList = [
    1462, 1422, 1383, 1346, 1311, 1277, 1245, 1214, 1184, 1156,
    1129, 1103, 1078, 1054, 1031, 1008, 987, 966, 947, 928,
    909, 891, 874, 858, 842, 826, 811, 797, 783, 769,
    756, 743, 730, 718, 707, 695, 684, 673, 663, 653, 643
];

// 溶解氧浓度（引用 adc1Voltage）
get doConcentration() {
    return (((this.adc1Voltage - 55) * 769 / 805 -
        (842 - RobotDataAccess.DoList[Math.round(this.waterTemperature)])) / 100);
}

// pH 值（引用 adc2Voltage）
get ph() {
    return ((-12.384 * this.adc2Voltage / 1000 + 40.93));
}

// 浊度（引用 adc3Voltage，含温度补偿）
get turbidity() {
    return ((-865.68 * ((this.adc3Voltage - (-0.0192 * (this.waterTemperature - 25))) / 1000) + 2047.19));
}

// TDS/电导率（引用 adc4Voltage，三次多项式）
get tds() {
    return (66.71 * this.adc4Voltage * 3 / 1000000000
          - (127.93 * this.adc4Voltage * 2 / 1000000)
          + (428.7 * this.adc4Voltage / 1000));
}
```
